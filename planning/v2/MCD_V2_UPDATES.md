# MCD v2 — Обновления, матрицы и сценарии

Дата: 2026-09-27. Статус: рабочая инвентаризация и план v2, не поручение на реализацию.

[Общая карта MCD v2](MCD_V2_CAPABILITY_BOUNDARIES.md) · [Сегменты](MCD_V2_SEGMENTS.md) · [Триггеры](MCD_V2_TRIGGERS.md) · [Обновления](MCD_V2_UPDATES.md)

Александр может редактировать этот файл напрямую. Перед обновлением перечитываем его, сохраняем операторские правки. «Реализовано» не означает свежую сквозную приёмку. Подписочные границы не выводим из расположения кода.

## Граница зоны

Уточнение 2026-10-01: [единые внешние пакеты операций](MCD_V2_SCENARIO_PACKAGES.md)
описывают новое отдельное поручение MCD/MCC. Оно отменяет привязку миграции
ZIP → Composer к версии 6 как обязательному шагу для 7. Локальный
предустановленный и пользовательский пакеты допускаются; прежнее ограничение
«standalone только same-line» отменено. Оплата относится к сервису, а не к
праву использования пакетов. Новый пакет из поддерживаемых примитивов
выпускается без обновления кода. Остальной план не запускается автоматически.

Обновления Mautic через ZIP/Composer и обновление самого MCD. Это не campaign update и не пересчёт сегмента.

## Утверждённая архитектура

- Один механизм исполнения MCD. MCC либо будущий сервис подписки поставляет управляемые данные и задания.
- Standalone MCD не содержит собственного управляемого каталога матриц и сценариев.
- Обновление Mautic внутри `x.y` бесплатно для standalone, ZIP и Composer.
- В managed-режиме внутри ветки проверяется матрица патчей точной target-версии; слоя plugin compatibility и его предупреждений нет.
- Между ветками дополнительно проверяются матрица плагинов и разрешённый сценарий. Разрешение принадлежит исходной ветке.
- Та же матрица плагинов определяет кандидатов установки. Новый обнаруженный release-line не получает разрешение перехода или совместимость плагина автоматически.
- Патч `1` требуется, `0` не требуется. Автоматическая обработка выполняется на установке; исторический каталог сохраняется. Не выдумывать обратную миграцию БД.
- Конкретные патчи, версии, порядок действий и применимость находятся в Assets/сценариях. Код — универсальное исполнение и валидация.
- Pinned version выбирает точную цель ветки; пустое поле использует обнаруженную версию из кеша этой ветки. Пин сам по себе не является запретом межветочного перехода.

## Managed-переходы между ветками

Решение Александра, 2026-09-30. Старый путь обновления между ветками —
источник практических наблюдений, а не образец для ремонта или копирования.
В частности, проблема с Twig показала, что разрешение Composer зависимостей
непосредственно на клиентском хосте не даёт воспроизводимого результата.

- Покрываем отдельными управляемыми сценариями все поддерживаемые соседние
  переходы: например, `4.4 → 5.1`, `5.1 → 5.2`, `5.2 → 6.0` и следующие
  поддерживаемые линии. Покрытие задаёт каталог; код не содержит список этих
  версий.
- Для каждого перехода существуют варианты `zip` и `composer`, если такой
  вариант установки поддерживается для обеих линий. Неподдерживаемое сочетание
  фиксируется в сценарии с причиной, а не имитируется.
- Сценарий живёт в MCC Assets, редактируется оператором и содержит исходную и
  целевую линию, допустимые типы установки, целевой артефакт, матрицы,
  разрешённые шаги, проверки до/после и условия восстановления. Переход
  выполняется через менеджер либо локально из пользовательского или
  предустановленного пакета. Подписка и оплата пакета не являются условиями
  исполнения, включая переход между ветками.
- `composer`-сценарий получает с management-сервера неизменяемый проверенный
  артефакт для точной цели: manifest, lock и подготовленное dependency/vendor
  содержимое либо эквивалентный упакованный проект. На хосте не выполняется
  новое Composer-разрешение зависимостей из внешних репозиториев.
- `zip`-сценарий получает проверенный ZIP-артефакт точной версии. Для обоих
  типов обязательны идентификатор артефакта, digest, происхождение, совместимый
  план и проверка до распаковки.
- Артефакт не содержит секретов или локальных данных инстанса. Исполнитель
  сохраняет локальные config/env, media, uploads, plugins и назначенные права
  по явной декларации сценария; backup и результат фиксируются отдельно.
- Редактируемость сценария не означает произвольный shell-код. Шаги выбираются
  из версионированного allowlist примитивов MCD; это сохраняет проверяемость,
  права и воспроизводимость.

Эта архитектура — критерий v2 и направление для отдельных поручений. Она не
разрешает сейчас чинить старый путь или запускать исторические переходы.

### Доводка MCC Assets перед реализацией

Проверка текущего MCC-каталога 2026-09-30: уже есть source/target,
`install_types`, `operator_enabled`, статусы, требования, упорядоченные typed
steps и запрет произвольного shell. До реализации v2 в schema/Assets должны
появиться:

1. `execution_mode=managed` и capability/provider contract для MCC или
   совместимого провайдера подписки;
2. идентифицированный артефакт: тип, origin, source revision, digest и точная
   Composer manifest/lock/dependency archive или ZIP target artifact;
3. идентичность, revision и digest plugin/patch matrices для каждого scenario
   edge, а не только boolean `plugin_matrix_required`;
4. опубликованный registry допустимых primitive steps и явный запрет shell
   текста в контракте Assets;
5. UI-представление режима, источника артефакта, matrix evidence и immutable
   provenance перед запуском.

## Готовность и текущая работа

Наличие handlers и зелёных unit/regression tests не доказывает свежую клиентскую сквозную приёмку. На дату создания пула managed 7.2.0 → 7.2.1 ещё не принят. Клиентский апгрейд запускает Александр. Здесь ведём границы v2, а исполнительные checkpoints — у владельцев и в памяти координатора.

## Критерии формализации v2

Отдельные результаты для standalone ZIP и Composer; один путь выбора managed-плана; отсутствие version/patch hardcode в новой политике; матрица exact target; безопасная обработка ранее применённых исправлений; предсказуемый progress/result; восстановление после сбоя; явная бесплатная/managed граница. Состав обязательной production-части v2 ещё не утверждён.
