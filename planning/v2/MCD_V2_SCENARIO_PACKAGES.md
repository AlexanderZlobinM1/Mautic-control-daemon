# MCD — единые внешние пакеты операций

Дата решения: 2026-10-01. Инициатор: Александр.
Статус: утверждённое направление и отдельное поручение на упрощение MCD/MCC;
формат ниже — предложение для согласования владельцами, не выпущенный контракт.

[Карта готовности](MCD_V2_CAPABILITY_BOUNDARIES.md) · [Обновления](MCD_V2_UPDATES.md)

## Принятое решение

MCD 2 остаётся рубежом готовности существующего продукта. Изменения вводятся
постепенно в текущую версию. Единственный агент исполняет внешние сценарии;
MCC является первым менеджером, но контракт не привязывается к его имени.

Убрать прибитую к версии 6 обязательную миграцию ZIP → Composer как условие
перехода на 7. Миграция типа установки — самостоятельная операция; обновление
версии — другая операция. Не заставлять пользователя выполнять первую ради
второй, если конкретный сценарий этого не требует.

Для плитки миграции в MCC действуют два продуктовых условия:

1. Установлена последняя поддерживаемая версия исходной ветки.
2. Менеджер располагает доступным сценарием, подходящим этой установке.

Кнопка и действие определяются описанием сценария. Нельзя зашивать в UI/API
правило «только 6», обязательность следующей соседней ветки или Composer.
При нажатии MCD получает выбранный пакет от менеджера и исполняет его.
Пакет привязан к конкретной ревизии: изменение каталога во время выполнения
не заменяет уже выбранные шаги и файлы.

«Последняя в ветке» относится к источнику миграции. Это не разрешение прыгать
к произвольной последней major-версии: цель и допустимый маршрут описывает
пакет. Существование сценария для другого источника не даёт кнопку этому
инстансу. Проверка свежести версии использует каталог менеджера, а не число
в исходнике. Неизвестные факты не выдаются за подтверждённые.

Сценарий может быть предустановлен в MCD. Такой пакет исполняется тем же
механизмом без доступного сервера менеджера; локальный интерфейс обнаруживает
его описанную возможность. Наличие локального пакета не создаёт в standalone
копию управляемого каталога MCC. По уточнению Александра от 2026-10-01
исполнение пакетов не ограничивается подпиской или оплатой отдельного пакета.
Same-line обновление остаётся бесплатным.

## Открытые сценарии и платный сервис

Пользователь может создавать, редактировать, устанавливать и исполнять свои
пакеты, обмениваться ими и использовать пакеты сообщества без MCC и подписки.
Это публично описываемая возможность продукта, а не внутренний обход.
Межветочная операция также не получает коммерческий запрет, если подходящий
пакет имеется локально. Платное предложение — сервис сопровождения и управления,
а не право исполнить отдельный сценарий; состав сервиса определяется отдельно.

Формат, целостность, применимость и capabilities проверяются одинаково для
всех источников. Доверие к издателю выбирает оператор: обязательная подпись
SalesSnap, проверка оплаты или обязательное обращение в MCC для собственного
пакета запрещены. Не подменять техническую совместимость платным entitlement.
Digest доказывает целостность, а не качество или безопасность сценария;
проверенный нами пакет и пакет сообщества имеют явно обозначенное происхождение.

## Что выносим из исходника

Конкретные версии и ветки; маршруты ZIP/Composer; условия применимости патчей;
зависимости, workaround и порядок шагов; набор ресурсов; правила предложения
операции; названия и тексты плиток; политика доступности сценария.

В MCD остаются обнаружение контекста установки, интерпретатор шагов, доставка
и проверка ресурсов, общий учёт выполнения и результатов. В MCC остаются
каталог, редактирование/публикация пакетов, выбор подходящей операции и общий
renderer. Конкретная операция не получает собственный новый endpoint или
отдельную зашитую кнопку при каждом выпуске сценария.

Упрощение не означает удаление общих проверок целостности пакета, путей
распаковки, прав, идентичности инстанса, конфликтующего активного запуска и
результата операции. Версионные/плагинные правила принадлежат сценарию,
а не скрытым дополнительным веткам кода. Для same-line сохраняется принятое
отсутствие plugin compatibility checks/stoppers/warnings.

## Предложение формата пакета

Один versioned manifest + шаги + файлы ресурсов в архиве либо content-addressed
наборе. Формат единый для core assets patches, обновлений ZIP/Composer,
миграции типа установки и известных workaround; тип операции — данные.
Оператор редактирует декларацию шагов, а не произвольную программу shell.

| Часть | Содержание |
| --- | --- |
| Идентичность | schema_version, package_id, revision, digest, publisher |
| Возможность | operation_kind, локализуемые label/description, source/target predicates, installation types |
| Совместимость | требуемые primitive capabilities и версия схемы; не произвольный порог версии агента |
| Ресурсы | относительный путь, тип, размер, SHA-256, immutable origin; архивы, manifests/locks, патчи, настройки-шаблоны |
| Шаги | упорядоченные typed actions; параметры и ссылки на ресурсы; условия выполнения и проверки результата |
| Восстановление | сохраняемые config/media/plugins/data, backup policy и явная последовательность recovery при применимости |
| Результат | ожидаемые версия/тип/факты; выполненные и пропущенные шаги; реальные ошибки и progress |
| Приёмка | точные исходные/целевые baselines, версия пакета, результаты в чистых песочницах |

Архив не содержит credentials и клиентских данных; пути безопасно ограничены
областью операции. Менеджер публикует проверенную неизменяемую ревизию.
Локально предустановленный пакет использует тот же manifest и resolver файлов.
Механизм доверия издателю, размер/формат архива, ресурсный кеш и API доставки
согласуют MCD и MCC с учётом уже существующих Assets — не создают второй каталог.

Composer-цель остаётся проверенным готовым артефактом менеджера, а не новым
разрешением зависимостей из внешних репозиториев на клиентском хосте.

Новый пакет из поддерживаемых примитивов не требует обновления MCD/MCC.
Новый неизвестный примитив требует реализации и выпуска исполнителя;
не поддерживаемая capability не должна запускаться вслепую. Не поддерживать
произвольный shell как обход этой границы.

## Рабочий чеклист и границы поручения

| Пункт | Сейчас | Требуемый результат |
| --- | --- | --- |
| Инвентаризация hardcode | Требует свежего source review владельцев | Точные пути MCD/MCC, UI/API/queue/CLI, правила 6→7 и ZIP→Composer |
| Единый формат | Предложение этого документа | Один согласованный producer/consumer contract, покрытие существующих Assets |
| Плитка миграции | Не принято по новым правилам | Источник latest + подходящий доступный сценарий; остальное определяется сценарием |
| Исполнение из менеджера | Существующие части, свежая приёмка не подтверждена | Fetch exact revision → execute → observed result через общий интерфейс |
| Локальный/пользовательский пакет | Требует инвентаризации | Тот же исполнитель без обязательного MCC, подписки и оплаты пакета; открытое создание и обмен |
| Удаление legacy hardcode | Новое поручение | После доказанной замены удалить лишние ветки, без второго параллельного исполнителя |
| Приёмка сценария | Доступны канонические песочницы | Реальный lifecycle Mautic, ZIP и Composer, source/target, negative applicability, reset |

Реализацию выполняют существующие владельцы MCD и MCC, координирует Емми.
Сначала согласовать контракт и показать инвентаризацию, затем перенести правила
и выполнить проверку. Старые незавершённые сценарные изменения не считаются
готовыми и не включаются целиком автоматически. Никаких customer миграций
или обновлений это поручение не запускает. Standalone scheduler и другие
независимые функции не переписываются под сценарии в рамках этой работы.

## Приёмка изменения

- Миграция не привязана в коде к 6 и не обязательна для обновления на 7.
- Latest исходник без подходящего сценария не получает кнопку; подходящий
  сценарий на не-latest исходнике не получает плитку миграции.
- Новый маршрут, цель или патч из существующих примитивов добавляется через
  пакет без изменения исходника MCD/MCC; не только посредством mock теста.
- Один и тот же пакет исполняется из менеджера и локально, когда это разрешено
  его технической применимостью; ядро не требует MCC, подписки или подписи SalesSnap.
- Проверенный пакет сохраняет config/data и даёт реальный ожидаемый результат;
  неуспех не превращается в success из кеша или одного сообщения об окончании.
- Старые Assets имеют отображение в новый формат, историю не удалять глобально.
- Сам сценарий проверяется в арендах канонических Mautic-Operations sandbox;
  после теста сохраняются результаты, файлы и БД сбрасываются к vanilla.

## История решений

2026-10-01: новое прямое поручение Александра supersedes прежнюю привязку
миграции к 6→7 и технический запрет любых локальных сценариев. Это не отменяет
планирование подписки и не даёт право включать все ранее отложенные переходы.

## Non-normative mapping examples

Ниже приведены примеры отображения существующих операций в единый формат
пакетов. Они не являются частью нормативного контракта и не разрешают
реализацию до принятия producer/consumer schema и sandbox evidence.

### A. Same-line ZIP 7.2.1 → Composer 7.2.1

Пакет выбирает точный Composer target artifact, связанный с
`composer.json`, `composer.lock` и подготовленным dependency/vendor
содержимым. Typed steps: `context`, `backup`, `prepare`, `verify`, `switch`,
`postverify`. На хосте не выполняется новое разрешение зависимостей.
Это обычный same-line сценарий; он не создаёт правило, что каждый ZIP
обязан переходить в Composer.

### B. Существующий Assets record `m7_import_tag_remediation`

Запись отображается по ссылке на `core_asset_patch/import-tag-detach`.
Сохраняются существующие typed vulnerable/fixed gates, patch SHA и rollback
семантика. Пакет ссылается на существующую идентичность Assets/patch и не
дублирует и не ослабляет её контракт.

### C. Managed cross-line latest 7.1.x → exact target

Пакет содержит выбранный вариант точного ZIP или Composer artifact и явные
предикаты применимости, включая latest-source evidence. Хост не разрешает
зависимости и не выбирает target из широкого version rule.

### Mapping существующих callers

- `web_ui`: `composer_move` и проверка major `{6, 7}`;
- `cache_dashboard`: Composer-only availability;
- `instance_ops`: очередь/remote command для `composer_move`;
- scenario validator: фиксированная Composer/four-step schema;
- scenario dispatch/prepared target: Composer-only binding;
- `mcc_cli`: Composer-only preflight;
- `release_policy`: adjacency gate.

Эти mapping points являются инвентаризацией. Общие queue/context/integrity/
result checks сохраняются. Старые caller branches удаляются или заменяются
только после принятия package contract и реального ZIP/Composer sandbox
приёмочного evidence.
