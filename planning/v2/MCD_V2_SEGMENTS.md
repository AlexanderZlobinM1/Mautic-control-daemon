## Граница зоны

Вращение сегментов: выбор eligible/due сегментов, порядок очереди, запуск, наблюдение, повторная допустимость и доказательства отсутствия пропусков. Кампании и их триггеры описаны отдельно.

## Рабочая карта

| Возможность | Реализовано сейчас | Standalone / MCC | Запланировано / требует доводки |
| --- | --- | --- | --- |
| Обычные круги priority / regular | Документирован implemented baseline, динамические веса и раздельные очереди | Исполнение и локальное состояние MCD; MCC управляет настройками | Свежая автономная проверка без MCC и явное описание критериев due |
| Запуск без ожидания завершения | Spawn-and-release, refill по running count, асинхронное наблюдение | MCD | Зафиксировать доказательства fairness, single-flight и восстановления |
| Сохранение состояния и рестарт | Документированы task state и восстановление работающих процессов | MCD | Проверить контракты restart/lost/timeout, не обещать по одному status |
| Recurring priority lane | Документирован отдельный lane по instance/segment, общий lock с обычным запуском | Локальный исполнитель; удалённая настройка через MCC | Разделить локальную конфигурацию и управляемую поставку; автономность проверить |
| SQL eligibility и веса | SQL due-набор, пересчёт весов и изменение active ID set описаны | MCD / локальная конфигурация, overrides MCC | Установить current-version доказательства, не переносить старые defaults без проверки |
| Ограничения и throttle | Профили, параллелизм и реакция на давление очереди документированы | MCD; централизованные профили MCC | Явно показать влияние на задержку, не объяснять пропуск нагрузкой без фактов |
| Сравнение автоматики с полным native циклом | Есть частичная разработка comparator и отдельные audit-артефакты | Исполнитель MCD, операционные доказательства у владельцев | Actual daemon/native integration и канал actionable-результатов не приняты |

## Правила оценки

- Отличать eligible → next_due → task creation → dispatch → daemon → execution → report. Для жалобы нужен доказанный участок потери, а не успешный ручной rebuild.
- Ошибка Mautic, отсутствующий или отключённый зависимый сегмент — не автоматически баг планировщика. Проверить причину один раз и классифицировать отдельно.
- Не менять слоты, бизнес-логику и профили для маскировки проблемы. Изменения профиля выполняет оператор.
- Полный контрольный цикл и расширенное логирование фокус-группы не считать работающими только по существованию автоматизации или утилиты comparator.
- Не задавать здесь новую фокус-группу или расписание: фактический состав и evidence остаются у владельцев действующего механизма.

## Что нужно уточнить для v2

Автономный режим без MCC; гарантии очередности и максимально допустимой задержки; диагностика причины ожидания; контракт restart/single-flight; штатные сигналы health; граница управляемой настройки и поддержки. Это вопросы плана, не новые исполнительные задания.
